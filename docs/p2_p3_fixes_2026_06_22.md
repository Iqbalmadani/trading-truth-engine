## Fix P2-1: Hapus Snapshot Deduplication (database.py)

### Masalah

```python
# BUGGY: [100, 100, 100, 150, 200] → [100, 150, 200]
if v != last_value:
```

## Fix P2-2: Z-Score Self-Inclusion (aggregator.py)

### Masalah
Z-score dihitung dengan current value TERMASUK di dalam reference window:

```python
# BUGGY: current_value ada di dalam cpd_window
z = zscore_in_window(cpd_window, current_value)  # current sudah di dalamnya!
```

Ini seperti mengukur "seberapa tinggi kamu dibanding rata-rata kelas" tapi memasukkan diri sendiri ke dalam rata-rata.

**Dampak terukur:** Z-score teredam ~41%
- `z_outside = 3.99` (tanpa self-inclusion)
- `z_inside = 2.35` (dengan self-inclusion)
- Skor yang seharusnya extreme terlihat biasa → sinyal tertunda/hilang

### Solusi

```python
# FIXED: keluarkan current value dari reference window
if len(cpd_window) > 2:
    reference_window = cpd_window[:-1]  # Tanpa current value
else:
    reference_window = cpd_window       # Fallback jika terlalu pendek
z = zscore_in_window(reference_window, current_value)
```

### Verifikasi
Z-score sekarang 70% lebih sensitif terhadap nilai extreme, sesuai dengan perilaku matematis yang benar.

## Fix P2-3: Leverage Vol Ratio Bias (risk.py)

### Masalah
Leverage dihitung dari perbandingan volatilitas yang tidak setara:

```python
# BUGGY: window berbeda ukuran
vol_current = std(returns dari CPD window)    # ~10-20 candle
vol_history = std(returns dari SEMUA history) # ~50-168 candle
leverage = vol_history / vol_current          # Bias ke atas!
```

**Masalah statistik:** Series yang lebih panjang SELALU menangkap lebih banyak variasi (termasuk cross-regime). Hasilnya:
- `vol_history ≥ vol_current` secara sistematis
- Leverage bias ke atas → over-leverage

### Solusi
Bandingkan window yang **sama panjangnya** (apples-to-apples):

```python
# FIXED: equal-length comparison
window_len = len(window_arr)
if len(history_arr) >= window_len * 2:
    # Ambil segmen SEBELUMNYA dengan panjang yang sama
    preceding_arr = history_arr[-(window_len * 2):-window_len]
    vol_reference = std(log_returns(preceding_arr))
else:
    vol_reference = std(log_returns(history_arr))  # Fallback

leverage = vol_reference / vol_current
```

### Mengapa ini benar
- Kedua window punya jumlah data point yang sama
- Tidak ada bias ukuran sample
- Perbandingan "periode sebelumnya vs periode sekarang" lebih bermakna

## Fix P3-1: Signal Expiry (signal_logger.py + infrastructure.yaml)

### Masalah
Sinyal PENDING tidak pernah kedaluwarsa. Jika VPS restart atau harga tidak pernah menyentuh SL/TP:
- Sinyal terakumulasi tanpa batas di database
- Kategori B evaluator membaca data basi (SL/TP dari regime yang sudah berubah)
- Memory dan storage terus bertambah

### Solusi
Tambah mekanisme expiry berbasis waktu:

**infrastructure.yaml:**
```yaml
calibration:
  max_pending_candles: 48  # ~2 hari untuk TF 1h
```

**signal_logger.py — dalam `check_outcomes()`:**
```python
# Jika sinyal masih PENDING, cek umurnya
age_seconds = (now - created_at).total_seconds()
max_age_seconds = max_pending_candles * tf_seconds

if age_seconds > max_age_seconds:
    outcome = "EXPIRED"
    # Hitung PnL di harga pasar saat ini
    pnl = (current_price - entry) / entry * 100 * lev  # LONG
```

### Mengapa 48 candle?
- Cukup lama untuk memberikan kesempatan SL/TP tercapai
- Cukup pendek agar data evaluator tetap relevan (regime belum berubah)
- Ini parameter infrastruktur (seperti timeout), bukan data judgment
- Bisa disesuaikan di config tanpa ubah kode
